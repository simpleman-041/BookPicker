今回はYondokuのタイトル検索と他の検索条件を組み合わせた際に発生する、
フロントエンドの検索状態不整合を修正してください。

今回の修正は機能バグ修正です。

セキュリティ対策の次工程にはまだ進まないでください。


現在の問題

タイトル検索欄へ文字列を入力して検索した後、
検索欄の文字を削除して空にしても、
Enterキーや検索ボタンで検索を確定しない限り、
内部のタイトル検索条件が残っています。

その状態で、

クイック条件
詳細フィルター
お気に入り

などを操作すると、
削除したはずのタイトル検索条件が再び使用されます。

場合によっては検索欄の表示内容まで以前の文字列へ戻ります。


例

1.
タイトル検索欄へ

Java

と入力してEnterで検索する。


2.
検索欄からJavaを削除して空欄にする。

この時点ではEnterを押さない。


3.
「興味のある順」などのクイック条件を押す。


期待する動作

タイトル検索条件は解除され、
興味のある順だけが適用される。


現在の動作

内部に以前の

Java

という検索条件が残っており、
クイック条件とJava検索が組み合わされる。

またはJavaが検索欄へ復元される。


修正方針

タイトル検索欄に表示されている現在値と、
APIへ送信するタイトル検索条件が不整合にならないようにしてください。

ただし、
入力文字が変わるたびにAPIへ検索リクエストを送る必要はありません。


クイック条件
詳細フィルター
お気に入り
タイトル検索ボタン
Enterによるタイトル検索

など、
検索または絞り込みを実際に実行する直前に、

現在のタイトル検索inputの値

を検索条件へ反映してください。


検索欄が空の場合は、
以前のSearchTitleなどのタイトル検索条件を明確に解除してください。

空文字列を以前の検索語へ置き換えないでください。


可能であれば、

現在の検索UIから検索条件を同期する処理

を共通化してください。

検索ボタン
Enter
クイック条件
詳細フィルター
お気に入り

それぞれで別々にタイトル検索状態を管理しないでください。


現在の部分一致、完全一致の仕様は維持してください。

検索欄が空の場合には、
部分一致、完全一致の選択状態そのものを変更する必要はありません。

次に文字を入力した際に現在選択中の一致モードを使用できる状態を維持してください。


重要

検索欄の表示値を、
古い内部検索状態から不用意に復元しないでください。

利用者が検索欄から文字を削除した操作を尊重してください。
