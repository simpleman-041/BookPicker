# BookPicker Codex 実装仕様

最終更新日: 2026-08-26

## 0. この文書の扱い

この文書は、現時点の BookPicker プロジェクトにおける最新仕様である。

Codex は、既存リポジトリ内の古いロードマップやプロジェクト構想より、この文書の仕様を優先すること。

特に、過去資料に残っている次の仕様は現行仕様ではない。

- 次に読む本を最大3冊提案する推薦機能
- 一覧画面で最小ページ数と最大ページ数を入力して絞り込むUI
- 最近登録した本を独立したクイック条件として表示する仕様

既存コードを変更するときは、まず現在の実装を確認し、既存のドメインルールと入力検証を可能な限り再利用すること。

大規模な全面書き換えは避け、小さな単位で変更すること。

各変更後にビルドと利用可能なテストを実行し、失敗した場合は原因を説明すること。

仕様が不明な部分を推測で決めて実装しないこと。この文書の「現時点で後回しにする事項」に該当する場合は、実装前に確認すること。

---

## 1. プロジェクトの目的

このアプリは、登録している本を把握し、読みたい本を探し、途中まで読んでいる本の読書を再開しやすくするためのWebアプリである。

当初予定していた「次に読む本を最大3冊提案する」専用推薦機能は採用しない。

代わりに、検索、フィルター、クイック条件、並び替えによって、ユーザー自身が次に読む本を素早く見つけられることを重視する。

## 3. 現在の実装状況

### バックエンド

現在、少なくとも次のAPIが存在する。

| 操作 | HTTPメソッド | URL |
|---|---|---|
| 本一覧取得、フィルター、並び替え | GET | `/api/books` |
| 本詳細取得 | GET | `/api/books/{id}` |
| 本登録 | POST | `/api/books` |
| 本の一般情報更新 | PUT | `/api/books/{id}` |
| 本削除 | DELETE | `/api/books/{id}` |
| 現在ページ更新 | PUT | `/api/books/{id}/progress` |
| 読了状態更新 | PUT | `/api/books/{id}/completion` |
| 表紙画像アップロード・差し替え | POST | `/api/books/{id}/cover` |

EF Core と SQLite は導入済み。

`Program.cs` では `UseDefaultFiles`、`UseStaticFiles`、`MapControllers` が使用されている。

### フロントエンド

現在、`wwwroot/index.html`、`wwwroot/css/style.css`、`wwwroot/js/app.js` が存在する。

JavaScriptから各APIをFetchし、一覧、詳細、編集、新規登録、進捗、読了、削除、既存Bookおよび新規登録時の表紙アップロードを操作できる。

## 4. アプリ名

画面上の表示名は正式に `Yondoku` とする。

コード内部のプロジェクト名、namespace、クラス名などは引き続き `BookPicker` を使用する。

Codexは、画面表示名の変更に伴って、プロジェクト名やnamespaceなどを `Yondoku` へ変更しないこと。

---

## 5. 一覧画面の目的

一覧画面は次の3つを目的とする。

1. 登録している本を把握する
2. 読みたい本を探す
3. 途中まで読んでいる本の読書を再開する

一覧画面は単なるデータベース検索画面ではなく、日常的な読書管理の入口として設計する。

---

## 6. 一覧画面の基本構成

現在のFigma案を基準に、PC向け画面は概ね次の構成とする。

```text
上部
├─ アプリ名
├─ タイトル検索
├─ 部分一致、完全一致の選択
└─ クイック条件

左側
└─ 詳細フィルター

中央
└─ 本カード一覧

本カード選択後
└─ 右側に詳細パネル
```

レスポンシブ対応は将来的に行うが、第一段階ではPC利用を中心にする。

---

## 7. 本カード

一覧の本カードには、情報を詰め込みすぎない。

表示する情報は次の3つ。

| 項目 | 内容 |
|---|---|
| 表紙 | 本を視覚的に識別するために表示 |
| タイトル | 本のタイトル |
| 進捗 | `現在ページ / 総ページ` の数値表示と進捗バー |

進捗は、`CurrentPage` と `TotalPages` を用いて、`現在ページ / 総ページ` と進捗バーを併記する。

本の詳細を開く操作は、表紙だけではなくカード全体を選択可能にする。

---

## 8. 詳細パネル

本カードを選択すると、一覧画面の右側にその本の詳細パネルを表示する。

右側パネルは、次の3用途で再利用する。

1. 選択した本の詳細表示
2. 選択した本の編集
3. 新しい本の登録

詳細表示では、少なくとも次の情報を扱う。

- タイトル
- `CurrentPage / TotalPages` の形式による進捗数値と進捗バー
- 表紙画像
- `Genre`
- `InterestLevel`
- `IsCompleted` をユーザー向けに表した読了状態
- `LastReadAt`

`ReadingStatus` は一覧カードの進捗表示や内部ロジックで利用し、詳細パネルには重複表示しない。

`Id` はユーザー向け情報として表示しない。`CoverImagePath` も文字列として表示せず、表紙画像の表示にだけ利用する。

`LastReadAt` は表示専用とし、ユーザーが直接編集する項目にはしない。

`編集` ボタンを押すと編集モードへ切り替わり、編集ボタンを保存ボタンへ切り替える。編集モードでは `CurrentPage` と `TotalPages` の両方を編集可能にする。

`保存` でバックエンドへ更新を送信し、成功後に詳細表示と一覧カードを最新状態へ更新する。

`キャンセル` では保存せず、編集前の表示状態へ戻る。

詳細パネル自体を閉じるための閉じる操作も用意する。

削除操作は詳細パネル下部へ配置し、危険操作であることが視覚的に分かるようにする。実際の削除処理では確認操作を挟む方針とする。

一覧画面の `＋ 本を追加` 操作で右側パネルを開き、新規登録モードを表示する。

新規登録に成功したら、本一覧を再取得して最新状態へ更新する。

---

## 9. Bookの現行データと追加データ

既存のBookモデルを基準に、第一完成版では次の情報を扱う。

| プロパティ | 意味 | ユーザーによる直接編集 |
|---|---|---|
| `Id` | 本を識別するID | 不可 |
| `Title` | タイトル | 可 |
| `Genre` | ジャンル | 可 |
| `TotalPages` | 総ページ数 | 可 |
| `CurrentPage` | 現在ページ | 可 |
| `InterestLevel` | 興味レベル | 可 |
| `IsCompleted` | 読了状態 | 専用操作のみ |
| `ReadingStatus` | 読書進捗 | 不可 |
| `LastReadAt` | 最後に読み進めた、または明示的に読了にした日時 | 不可 |
| `CoverImagePath` | 表紙画像のパスまたはURL | 可 |

既存のBookモデルにある入力検証や不正状態を防止するルールは維持する。

タイトル長やページ数上限など、既存コードとこの文書で値が明示されていない検証条件については、Codexが新しい値を推測して変更しないこと。

新規登録では `CoverImagePath` を任意で指定できる。未指定でも登録を許可する。

一般編集では、各プロパティを途中状態で1つずつ変更して検証するのではなく、リクエストされた最終状態全体の整合性を先に検証してから反映する。

たとえば、現在 `TotalPages = 500`、`CurrentPage = 400` の本を、1回のリクエストで `TotalPages = 300`、`CurrentPage = 250` へ変更することは、最終状態が `CurrentPage <= TotalPages` を満たすため有効とする。

最終状態で `CurrentPage > TotalPages` になる変更は、自動補正せず `400 Bad Request` とする。したがって、`CurrentPage` を変更せずに `TotalPages` を現在ページ未満へ減らす変更も `400 Bad Request` とする。

最終状態で `CurrentPage < TotalPages` になった場合は、`IsCompleted` を自動的に `false` にする。

最終状態で `CurrentPage == TotalPages` になった場合でも、`IsCompleted` を自動的に `true` にはしない。

---

## 10. ReadingStatus

`ReadingStatus` はユーザーが直接変更しない。

`CurrentPage`、`TotalPages`、`IsCompleted` をもとにBook側で自動更新する。

既存の自動計算ロジックを尊重する。

現在使用している状態名は次のとおり。

```text
NotStarted
EarlyStage
MidWay
LateStage
Completed
```

クイック条件の「もう少しで読了」は `LateStage` の本を対象とする。

---

## 11. IsCompleted

最終ページへ到達しただけでは自動的に読了にはしない。

基本フローは次のとおり。

```text
ユーザーが専用の「読了にする」操作を行う
↓
CurrentPage が TotalPages 未満なら TotalPages へ進める
↓
IsCompleted が true
↓
ReadingStatus が Completed
↓
LastReadAt を現在のUTC日時へ更新
```

ユーザーが専用の「読了にする」操作を行った場合は、現在の `CurrentPage` に関係なく読了にできる。

`CurrentPage` が `TotalPages` 未満の場合は、システムが `CurrentPage` を `TotalPages` へ進め、`IsCompleted` を `true`、`ReadingStatus` を `Completed` にする。

`CurrentPage` がすでに `TotalPages` と一致している場合も、`IsCompleted` を `true`、`ReadingStatus` を `Completed` にする。

読了操作はユーザーが明示的に読み終えた操作とみなし、操作前の `CurrentPage` に関係なく、成功時は `LastReadAt` を現在のUTC日時へ更新する。

読了済みの本には「読了解除」の専用操作を用意する。

読了解除では `IsCompleted` だけを `false` にし、`CurrentPage` と `LastReadAt` は変更しない。`ReadingStatus` は現在の `CurrentPage` と `TotalPages` から再計算する。

最終ページまで到達した本を読了解除した場合は、`CurrentPage` は `TotalPages` のまま、`ReadingStatus` は `LateStage` になる。

読了済みの本で `CurrentPage` を `TotalPages` 未満へ戻した場合は、自動的に `IsCompleted` を `false` にして読了状態を解除する。

`IsCompleted` を通常の編集フォーム内のチェックボックスとして直接変更させない。

---

## 12. LastReadAt

新しく `LastReadAt` をBookへ追加する。

型は日時を表現でき、未読状態を表現できるnullable型とする。

新規作成時は `null`。

通常の進捗更新と一般編集における更新条件は厳密に次のとおり。

```text
新しい CurrentPage > 更新前の CurrentPage
↓
LastReadAt を現在のUTC日時へ更新
```

`LastReadAt` はUTCで保存する。

この更新ルールは、現在ページ専用のprogress APIだけでなく、一般編集APIで `CurrentPage` を増加させた場合にも適用する。

通常の進捗更新と一般編集では、次の場合は更新しない。

- `CurrentPage` が同じ
- `CurrentPage` が減少した
- タイトルを変更した
- ジャンルを変更した
- 総ページ数を変更した
- 興味レベルを変更した
- 表紙を変更した

これとは別に、ユーザーが明示的に「読了にする」操作を行った場合は、`CurrentPage` がすでに `TotalPages` と一致している場合も含めて `LastReadAt` を現在のUTC日時へ更新する。

読了解除では `LastReadAt` を変更しない。

「最近読んだ」は `LastReadAt` の降順で並び替える。

`LastReadAt` が `null` の本は、最近読んだ順では日時を持つ本より後に表示する。

---

## 13. 表紙画像

表紙画像を正式仕様として採用する。

Bookには画像そのものを保存せず、`CoverImagePath` として画像の場所を表す文字列を保存する。

対象はアプリ内の相対パスまたは利用可能な画像URLを想定する。

表紙画像の未設定を許可する。

`CoverImagePath` が `null`、空文字、または利用できない場合はデフォルト表紙画像を表示する。

第一段階のデフォルト表紙には、中立的なローカルプレースホルダーを使用する。

既存Bookの表紙画像は、次の専用APIでアップロードおよび差し替えできる。

```text
POST /api/books/{id}/cover
Content-Type: multipart/form-data
フォームフィールド名: file
```

対象Bookが存在しない場合は `404 Not Found` とする。

空ファイル、5MBを超えるファイル、許可外の拡張子、拡張子と一致しないContent-Typeは `400 Bad Request` とし、ユーザーが原因を理解できる日本語メッセージを返す。

許可する拡張子とContent-Typeの組み合わせは次のとおり。

| 拡張子 | Content-Type |
|---|---|
| `.jpg` | `image/jpeg` |
| `.jpeg` | `image/jpeg` |
| `.png` | `image/png` |
| `.webp` | `image/webp` |

画像は `wwwroot/uploads/covers` へ保存する。保存先が存在しない場合はサーバー側で作成する。

元ファイル名は保存に使用せず、サーバー側でGUIDの `N` 形式と検証済みの小文字拡張子を組み合わせた一意なファイル名を生成する。

保存後の `CoverImagePath` は次の形式とする。

```text
/uploads/covers/{GUIDのN形式}.{検証済み拡張子}
```

新しい画像ファイルを保存して `CoverImagePath` を更新し、`SaveChangesAsync` が成功した後に限り、以前の不要なローカル表紙を削除する。

古い表紙の削除対象は、`/uploads/covers/` の直下にあり、本機能が生成するGUIDの `N` 形式と許可拡張子に一致するファイル名だけとする。デフォルト表紙、`http` または `https` の外部URL、管理対象外のローカルパス、サブディレクトリや `..` を含むパスは削除しない。

ファイルシステム上の保存先と削除対象はサーバー管理のWebルートおよび固定ディレクトリから構築し、ユーザー入力を物理パスとして使用しない。DB更新までに失敗した場合は、作成済みの新規画像を可能な範囲で削除する。

詳細ビューでは表紙をボタンとしてクリックまたはキーボード操作できる。`input type="file"` の `accept` には許可形式を設定し、選択後は `FormData` の `file` として専用APIへ送る。JavaScriptからContent-Typeヘッダーは指定せず、multipart boundaryの生成をブラウザへ任せる。

アップロード中は表紙の再選択、詳細内の更新操作、編集、削除、パネルを閉じる操作を一時的に無効化し、状態を詳細パネル内へ表示する。APIエラーも詳細パネル内へ日本語で表示する。

アップロード成功後は `GET /api/books/{id}` と現在の検索・詳細フィルター・クイック条件を保持した `GET /api/books` を再実行する。現在選択中のBookを維持したまま詳細と一覧をサーバーの最新状態へ更新する。

編集ビューでも同じ表紙選択UIを利用できる。ただし選択直後にはアップロードせず、選択Fileと`URL.createObjectURL`で生成したプレビューURLを編集モード中だけJavaScript側に保持する。選択済みの表紙には「変更予定」を表示する。

編集キャンセル、編集状態の破棄、別の画像の再選択では保持中のFile参照を破棄し、不要になったObject URLを`URL.revokeObjectURL`で解放する。キャンセル時に表紙APIは呼ばず、元のBookの表紙を表示する。

編集保存で表紙変更がある場合は、まず既存の一般編集APIを実行し、成功した後だけ既存の表紙アップロードAPIを呼ぶ。一般編集が失敗した場合は選択Fileとプレビューを維持し、表紙アップロードは実行しない。一般編集成功後に表紙アップロードだけ失敗した場合は、最新Bookを取得して一般編集済みの実際の状態を表示し、表紙変更だけが失敗したことを通知する。

画像読み込みに失敗した場合は、既存のデフォルト表紙フォールバックを維持する。

新規登録フォームでは表紙画像を任意で選択できる。初期表示はデフォルト表紙とし、選択直後は`URL.createObjectURL`によるローカルプレビューだけを表示する。選択FileとプレビューURLは新規登録モード中だけ保持し、キャンセル、登録完了、作成状態の破棄、画像再選択時に不要なObject URLを解放する。

新規登録時は、まずローカルFile情報を含めない既存の`POST /api/books`でBookを作成する。表紙が選択されている場合に限り、レスポンスから取得・検証したBook Idを使って`POST /api/books/{id}/cover`を実行する。Idを安全に取得できない場合は、別の推測方法を使わず表紙アップロードを行わない。

Book作成が失敗した場合は、選択Fileとプレビューを保持したままフォームにエラーを表示し、表紙アップロードは実行しない。Book作成後の表紙アップロードだけが失敗した場合は、Book自体は登録済みとして一覧を再取得し、可能なら作成Bookの詳細と実際に保存された表紙状態を表示したうえで、表紙設定失敗を通知する。

## 14. タイトル検索

タイトル検索を維持する。

検索方式は部分一致と完全一致を選択できる。

現在の既存フィルター実装に `SearchTitle` と `TitleMatchMode` が存在する場合は、それを再利用する。

検索条件は左側フィルターおよびクイック条件と併用できる。

---

## 15. 左側の詳細フィルター

詳細フィルターは、クイック条件より細かな条件を指定するために使用する。

使用する条件は次のとおり。

- `InterestLevel`
- `Genre`
- `ReadingStatus`

3項目はいずれもselect形式の入力UIで扱う。

複数種類の条件が指定された場合はAND条件で組み合わせる。

`InterestLevel` の意味は既存実装を維持し、指定値以上の本を対象とする。

最小ページ数と最大ページ数をユーザーが数値入力するUIは採用しない。

既存バックエンドに `MinPages` と `MaxPages` が残っていても、第一完成版の一覧UIからは使用しない。

削除やリファクタリングは他のコードへの影響を確認してから別途行う。

---

## 16. クイック条件

上部には、ユーザーが頻繁に使う検索や並び替えをワンクリックで適用できるクイック条件を置く。

クイック条件は単一選択とし、同時に複数のクイック条件を選択しない。

クイック条件は、タイトル検索および左側の詳細フィルターと併用する。

つまり、詳細フィルターで候補を絞ったあと、その結果にクイック条件を適用できる。

現時点のクイック条件は次のとおり。

| 表示名 | 処理 |
|---|---|
| `すべて` | クイック条件を通常状態へ戻し、`Id` 降順 |
| `興味のある順` | `InterestLevel` 降順 |
| `もう少しで読了` | `ReadingStatus == LateStage` |
| `たっぷり読む` | `TotalPages` 降順 |
| `短めに読む` | `TotalPages` 昇順 |
| `最近読んだ` | `LastReadAt` 降順、nullは最後 |

`すべて` を押しても、タイトル検索や左側の詳細フィルターは消さない。

`すべて` は、クイック条件だけを通常状態へ戻す。

SQLやEF Coreで取得順序に依存せず、`Id` 降順は明示的に指定すること。

「新しい本」というクイック条件は採用しない。

---

## 17. ページ数条件の変更

旧仕様の `MinPages` と `MaxPages` による一覧画面のページ数範囲検索は主要UIから外す。

「たっぷり読む」と「短めに読む」はページ数によるフィルターではなく、`TotalPages` による並び替えである。

```text
たっぷり読む
↓
TotalPages 降順

短めに読む
↓
TotalPages 昇順
```

Codexは、この2つを `MinPages` や `MaxPages` の値へ変換する実装にしないこと。

---

## 18. 新しい本の扱い

新しい本を表示する専用機能は作らない。

通常状態の一覧を `Id` 降順で表示するため、結果として最近登録した本が上に現れる。

`CreatedAt` は、この目的だけのためには追加しない。

将来的に登録日時そのものが必要な機能を追加するときに再検討する。

---

## 19. 編集API

現在、現在ページ専用の更新APIは存在するが、本の一般情報をまとめて編集するAPIは未実装。

詳細パネルの編集機能に対応するため、次のAPIを追加する方向とする。

```text
PUT /api/books/{id}
```

このAPIでは、ユーザーが編集可能なBook情報を更新する。

`CoverImagePath` も一般編集APIで変更可能とする。

ただし、`ReadingStatus` と `LastReadAt` をリクエストから直接設定させない。

`IsCompleted` も一般編集APIでは直接変更させず、専用操作を使用する。

Bookのプロパティを単純にpublic setterへ変更して整合性を崩すのではなく、既存のドメイン設計に合わせて安全な更新方法を用意する。

入力値はプロパティごとに逐次反映して検証せず、リクエストされた最終状態全体を組み立てて整合性を検証してから反映する。

最終状態で `CurrentPage > TotalPages` となる場合は、自動補正せず `400 Bad Request` とする。同じリクエストで両方を変更し、最終状態が `CurrentPage <= TotalPages` なら有効とする。

一般編集APIによって `CurrentPage` が更新前より増加した場合も、`LastReadAt` を現在のUTC日時へ更新する。

最終状態で `CurrentPage < TotalPages` となった場合は `IsCompleted` を `false` にする。`CurrentPage == TotalPages` となっただけでは `IsCompleted` を `true` にしない。

---

## 20. 読了API

読了状態を変更する専用APIを次の仕様で追加する。

```text
PUT /api/books/{id}/completion
```

リクエストBodyは次のいずれかとする。

```json
{ "isCompleted": true }
```

```json
{ "isCompleted": false }
```

要件は次のとおり。

```text
読了にする
CurrentPage が TotalPages 未満なら TotalPages へ進める
IsCompleted を true にする
ReadingStatus を Completed にする
LastReadAt を現在のUTC日時へ更新する

読了解除
IsCompleted を false にする
CurrentPage と LastReadAt は変更しない
ReadingStatus を現在の進捗から再計算する
```

`CurrentPage < TotalPages` の状態で `{ "isCompleted": true }` を指定した場合も、新しい読了ルールに従って成功する。

存在しない本は `404 Not Found` とする。

成功時は `204 No Content` とする。

---

## 21. エラー処理

既存のBook側で入力不正を `ArgumentException` などによって防いでいる場合は、その方針を維持する。

Controller側ではユーザー入力によるドメインエラーを適切な `400 Bad Request` に変換する。

存在しないIDは `404 Not Found`。

読了APIの成功時は `204 No Content` とする。その他のAPIの成功時ステータスは現在のAPI設計とREST上の意味を考慮する。

フロントエンドではAPIエラーを無視せず、ユーザーが原因を理解できる形で表示する。

---

## 22. 推薦機能の廃止

専用の推薦機能は第一完成版から削除する。

次のようなエンドポイントやサービスは新規実装しない。

```text
POST /api/books/recommendations
RecommendationService
最大3冊を選ぶ専用ロジック
```

旧資料に推薦機能の記述が存在しても、この文書を優先する。

現在の検索、フィルター、クイック条件によって「次に読む本を見つける」体験を提供する。

## 23. Codexに求める実装姿勢

このプロジェクトは学習目的も含む。

Codexは単に動作するコードを大量生成するのではなく、既存設計を尊重して小さな差分で実装すること。

各タスク完了時に次を報告する。

1. 変更したファイル
2. 変更した理由
3. 重要な設計判断
4. 実行したビルドまたはテスト
5. 残っている問題
6. ユーザーが理解しておくべき新しい概念

既存コードに重大な設計上の問題がある場合は、勝手に全面修正せず、問題点と修正案を先に説明すること。

## 25. 第一完成版の受け入れ条件

第一完成版では少なくとも次を満たす。

- 登録済みの本をカード一覧で表示できる
- 表紙、タイトル、`現在ページ / 総ページ`、進捗バーを確認できる
- 表紙未設定時に中立的なローカルのデフォルト画像が表示される
- 詳細パネルの表紙をクリックして、既存Bookの表紙をアップロードまたは差し替えできる
- 表紙アップロードで拡張子、Content-Type、空ファイル、5MB上限がサーバー側で検証される
- 表紙アップロード成功後に詳細と現在の条件を維持した一覧を再取得できる
- 表紙アップロードの検証エラーを詳細パネル内で確認できる
- 管理対象の古いローカル表紙だけが安全に削除される
- `＋ 本を追加` から右側パネルを新規登録モードで開ける
- 新規登録で `CoverImagePath` を任意指定でき、未指定でも登録できる
- 新規登録フォームで任意の表紙画像を選択・プレビューでき、登録成功後に表紙アップロードできる
- 新規登録成功後に本一覧が最新状態へ更新される
- カード選択で右側詳細パネルを開ける
- 右側パネルを詳細表示、編集、新規登録の3用途で再利用できる
- 詳細情報を確認できる
- 編集可能項目を編集して保存できる
- 一般編集APIで `CoverImagePath` を変更できる
- 一般編集APIがリクエストの最終状態全体を検証してから変更を反映する
- 最終状態で `CurrentPage > TotalPages` になる一般編集は自動補正されず `400 Bad Request` になる
- 最終状態で `CurrentPage < TotalPages` になると `IsCompleted` が `false` になる
- `CurrentPage == TotalPages` になっただけでは `IsCompleted` が `true` にならない
- `ReadingStatus` を直接編集できない
- `LastReadAt` を直接編集できない
- progress APIまたは一般編集APIで `CurrentPage` が増加したときだけ `LastReadAt` がUTC日時で更新される
- `PUT /api/books/{id}/completion` で読了状態を変更でき、成功時に `204 No Content` になる
- 最終ページ未到達で読了にすると `CurrentPage` が `TotalPages` へ進み、`IsCompleted` が `true`、`ReadingStatus` が `Completed` になる
- 読了操作では、操作前の `CurrentPage` に関係なく `LastReadAt` が現在のUTC日時へ更新される
- 読了解除では `CurrentPage` と `LastReadAt` が変更されず、最終ページでは `ReadingStatus` が `LateStage` になる
- 本を削除できる
- タイトルを部分一致、完全一致で検索できる
- `InterestLevel`、`Genre`、`ReadingStatus` の詳細フィルターをselect形式で利用できる
- クイック条件を単一選択できる
- クイック条件と詳細フィルターを併用できる
- `すべて` で `Id` 降順になる
- `興味のある順` で `InterestLevel` 降順になる
- `もう少しで読了` で `LateStage` のみ表示できる
- `たっぷり読む` で `TotalPages` 降順になる
- `短めに読む` で `TotalPages` 昇順になる
- `最近読んだ` で `LastReadAt` 降順になる
- SQLiteに変更が保存され、再起動後も残る
- ユーザー入力エラーを適切に表示できる
- 専用推薦機能を実装していない
